# Management Playbook

This file stores reusable lessons, not every detail.

## Default Management Stance

- Start with facts.
- Take responsibility before attribution.
- Convert reflection into behavior change.
- Close loops with owner, node, output, and follow-up.
- Translate governance and technical work into business value.

## Core Playbook Rules

### Upward Reporting

Use:

1. conclusion
2. plan
3. owner
4. timeline
5. expected result
6. needed resource
7. risk and fallback

Avoid leading with explanations.

### Team Member Issue

Check both performance and human system:

- capability
- attitude
- role boundary
- pressure
- emotional energy
- support resources
- recognition
- growth path

### Cross-Team Collaboration

Before escalation:

- clarify stakeholder KPI
- reduce complexity for the other side
- prepare multiple options
- identify shared benefit
- give shared credit
- create a small commitment first

### Long-Term Coaching Safeguards

For six-month use at 1-2 sessions per week:

- weekly session opening: check latest facts, priority, emotional state, and open commitments
- review open commitments at the start of follow-up sessions
- monthly pattern review: summarize repeated scenes, blind spots, and behavior change every 4-6 sessions
- quarterly personal context refresh: update role, goals, team state, and stale context
- produce a pattern summary every 4-6 sessions
- mark stale context when assumptions may have changed
- check whether reflection produced behavior change
- commitment follow-up: each commitment needs owner, date, observable result, and status
- playbook update criteria: add a lesson only if it repeats, has a verified result, or the user explicitly chooses it as a principle
- anti-repetition: when advice repeats, ask what changed, what was tried, and what result appeared before giving more advice
- update this playbook only when a lesson is reusable
- rotate frameworks so the user does not overfit to one lens
